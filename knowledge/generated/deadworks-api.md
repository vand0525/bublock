### UI.UI

Entry point for the UI message manager. Use `Panel` to obtain a handle for a logical UI panel; the panel id binds to the panorama-side panel script registered with the same id via DW.registerPanel({ id: "..." }). A panel stays up until you destroy it, the player leaves, or the map changes. Every panel is gone on a new map, so treat any you were tracking as closed in `OnStartupServer` and show them again as players arrive.

- `int BurstSize` (static): Per-recipient burst capacity (token-bucket size). Defaults to 24.
- `int BytesPerSecond` (static): Per-recipient wire budget in bytes/s. Defaults to 16 KB/s. This is the budget that matters: frames go out on the reliable net channel, which disconnects the client on overflow rather than throttling. Raise it only with real players on a real server, watching for choke and drops.
- `float CaptionLengthSeconds` (static): How long each caption frame lives on the client, in seconds. Defaults to 0.2. This governs throughput, not bandwidth. The client renders at most six captions at a time and silently discards any beyond that, so the channel tops out at 6 / CaptionLengthSeconds frames per second — about 5/s at the game's default linger, which is why the transport felt slow regardless of rate or frame size. The send rate is clamped to stay inside this automatically. Lower means more throughput but less time for the client to build its panel and for the mod to read it. Do not go near a frame time.
- `float CaptionLingerSeconds` (static): The client's cc_linger_time, which is added to every caption's own length to get its expiry. Defaults to 0.3, matching what the addon asserts on the client. This is not a knob you set to change client behaviour — the addon owns that. It exists so `MaxFramesPerSecond` tells the truth. If you ship an addon with a different CC_LINGER, set the same value here or the channel will pace itself against a pool that recycles slower than it thinks.
- `int MaxFrameLength` (static): Bytes of wire payload per caption frame. Defaults to 3800. Hard-capped just under 4000: the client copies caption text into a fixed char[4096] stack buffer with no bounds check, so larger frames corrupt its stack. Larger frames are otherwise strictly better — each frame costs one usermessage, so fewer/fatter frames means less reliable-channel pressure for the same payload.
- `double MaxFramesPerSecond` (static): Frames per second this channel can actually deliver, derived from `CaptionLengthSeconds` and the client's six-caption display pool. Read-only. Pace recurring updates against this. ### UI.UINode

Base type for nodes in a code-driven UI tree. Built via the factories on `UI` (UI.Vertical, UI.Label, etc.) and shipped to the client by `BuildLayout`.

- `List<UINode> Children`
- `List<ValueTuple<string, string>> HoverStyles`: Styles applied while the pointer is over this node, and reverted when it leaves. Panorama's :hover needs a stylesheet, which a server-built tree has no way to ship — the client applies these directly instead, so each plugin picks its own colours with nothing shared or pre-registered. Declaring any of these makes the node hit-testable, since a node that ignores the pointer can never see it arrive.
- `string Id`
- `List<ValueTuple<string, string>> PressStyles`: Styles applied while the pointer is held down on this node, on top of any hover styles, and reverted on release. Hover and press are the only states the client has to own: the server rebuilds the tree whenever game state changes, so anything it knows — selected, disabled, whose turn it is — is already expressible by sending different styles. It just cannot see the pointer.
- `List<ValueTuple<string, string>> Styles`: Styles applied to this node, in declaration order. Each entry is a (property, value) pair (e.g. ("horizontal-align", "left")). Use `WithStyle``1` or `WithStyles``1` to add entries fluently. Property names should be CSS kebab-case so the wire-format token compressor can replace common ones with single-byte codes.
- `List<ValueTuple<string, string, string>> Transitions`: Client-side transitions declared on this node, added with `WithTransition``1`. Kept apart from `Styles` because Panorama expresses several transitions as parallel comma-separated lists across three properties. Appending them as ordinary styles would make a second call silently override the first rather than adding to it; collected here they compose, and the encoder emits the matched lists.

### UI.UIPanel

Handle for a logical UI panel. Methods enqueue updates onto each recipient's rate-limited queue; the actual subtitles are emitted from the host runtime's per-frame tick. Field updates are coalesced latest-wins per (panel, key).

- `string Id`
- `void Animate(RecipientFilter to, string nodeId, string property, string value, string duration, string timing)`: Change `property` to `value` over `duration`, letting the client interpolate. This is the form to reach for whenever the destination is known in advance. A thirty-second bar is one call, not one call per frame: the client animates at its own rate, the result is smoother than this channel could deliver, and it keeps running through a server hitch because the server is no longer involved. Equivalent to declaring `WithTransition``1` on the node and then calling `SetStyle`, and safe to call on a node that already declares one.
- `void AppendChild(RecipientFilter to, string parentId, UINode child)`: Append a subtree under an existing node in the panel's host. Far cheaper than `BuildLayout` when only a small piece of the tree is changing — typical row addition fits in 1–2 wire chunks. `parentId` must match a node id inside the existing tree (resolved client-side via FindChildTraverse).
- `UIUpdate Build()`: Begin building a multi-op message that ships in one logical send.
- `void BuildLayout(RecipientFilter to, UINode root)`: Replace the panel's DOM tree on each recipient. The bootstrap creates a host panel under the HUD root if needed, wipes any existing children, and walks the tree calling $.CreatePanel for each node. Subsequent `Set` calls on the same panel auto-bind to Labels by id.
- `void Clear(RecipientFilter to)`: Tells the panel script to clear its state.
- `void DestroyLayout(RecipientFilter to)`: Destroy the panel's host on each recipient and forget its registration.
- `void LoadXml(RecipientFilter to, string xmlPath)`: Tell the bootstrap to BLoadLayout an XML file from the client's mod tree under a fresh host panel. The XML's own <scripts> block runs in an isolated domain, so the addon must be self-contained (no DW access from inside). Use `DestroyLayout` to tear it down.
- `UIPanel On(string eventName, Action<UIEvent> handler)`: Register a handler for an event the panel fires client-side via DW.send(panelId, eventName, ...args). Latest registration wins.
- `void Precache(RecipientFilter to, UINode root)`: Ship the layout to each recipient and let the bootstrap parse + cache it without instantiating a host. After this completes, a much smaller `Show` call (a single chunk, no payload) renders the panel instantly. Useful for HUDs whose structure stays fixed and only field values change at runtime — precache once, set fields freely.
- `void ReleaseCursor(RecipientFilter to)`: Gives back the cursor this panel asked for with `RequestCursor`.
- `int Reload(RecipientFilter to)`: Re-send whatever layout each recipient was last given for this panel, tearing the addon down and rebuilding it. The path comes from what the channel already retained, so you don't have to pass it again. Exists for the edit loop: change an addon's .xml or .js and reload it without restarting the client. Returns how many recipients had a layout to reload.
- `void RemoveChild(RecipientFilter to, string targetId)`: Remove a child node by id from the panel's host. Single-chunk wire op.
- `void RequestCursor(RecipientFilter to)`: Frees the mouse cursor for each recipient so they can click this panel's buttons. While it's free they can't move, aim or cast. It stays free until `ReleaseCursor` or `DestroyLayout`; when several panels ask for it, it stays free until the last one lets go.
- `void SendRaw(RecipientFilter to, string text)`: Sends an opaque text payload to the panel script's onRaw handler.
- `void Set(RecipientFilter to, string key, object value)`: Reliable field update — eventually delivered, latest value wins.
- `void SetStyle(RecipientFilter to, string nodeId, string property, string value)`: Change one style property on a node already in the panel's tree, without rebuilding it. `nodeId` is the node's Id, resolved client-side. Patches coalesce latest-wins per (node, property), so calling this every frame is safe: offering updates faster than the channel drains costs nothing but intermediate values. `BuildLayout` has no such coalescing — driving it per-frame grows an unbounded backlog and the panel falls progressively further behind. For anything whose path is known in advance, prefer one patch plus a CSS transition over a stream of them: UI.Panel("hud").SetStyle(to, "bar", "transition-duration", "30s"); UI.Panel("hud").SetStyle(to, "bar", "width", "0%"); The client then interpolates at its own framerate, which is smoother than this channel could ever be and costs nothing after the first patch.
- `void SetStyles(RecipientFilter to, string nodeId, ValueTuple<string, string>[] entries)`: Change several style properties on one node at once. Cheaper than separate `SetStyle` calls — they share the node id on the wire.
- `void SetUnreliable(RecipientFilter to, string key, object value)`: Best-effort field update — dropped under bandwidth pressure, latest value wins.
- `void Show(RecipientFilter to)`: Render a previously-precached panel on each recipient. No-op (and logs on the client) if the panel was never precached. Pre-existing state from `Set` calls is auto-applied to matching Labels after the host is created.

### Utils.Zone

A box in the world that tells you when players walk into it and out of it, through `Entered` and `Left`. Use it for checkpoints, start and finish lines, reset areas, safe areas, or anything else you'd otherwise check by hand every frame.

- `Vector3 Center`: The middle of the zone.
- `bool Enabled`: Turns the zone on and off. While off, everyone counts as outside: players inside get `Left`, and no `Entered` fires until it's turned back on.
- `Vector3 Maxs`: The corner with the highest coordinates. Setting it below `Mins` on an axis swaps the two on that axis.
- `Vector3 Mins`: The corner with the lowest coordinates. Setting it beyond `Maxs` on an axis swaps the two on that axis.
- `string Name`: Optional label, handy in logs and when one handler serves several zones.
- `int OccupantCount`: How many players are inside right now.
- `IReadOnlyList<CCitadelPlayerController> Occupants`: The players inside right now.
- `Vector3 Size`: How big the zone is along each axis.
- `object Tag`: Anything you want to attach to the zone, such as a checkpoint number.
- `bool Contains(Vector3 point)`: True if `point` is inside the zone. Points exactly on the edge count as inside.
- `void Dispose()`: Stops the zone for good. No more events fire, not even `Left` for players still inside.
- `Zone FromCenter(Vector3 center, Vector3 size)` (static): Creates a zone of the given `size` with its middle at `center`.
- `Zone FromOrigin(Vector3 origin, Vector3 minsOffset, Vector3 maxsOffset)` (static): Creates a zone from a point and corners relative to it, the way map triggers are set up. For example, an origin on the floor with `minsOffset` (-64, -64, -8) and `maxsOffset` (64, 64, 96) covers a 128 wide area from just below the floor to about head height.
- `bool IsInside(int slot)`: True if the player in `slot` was inside at the last check.
- `bool IsInside(CBasePlayerController player)`: True if the player in `slot` was inside at the last check.
- `void MoveTo(Vector3 center)`: Moves the zone so its middle is at `center`, keeping its size. Enter and leave events follow as for `SetBounds`.
- `void ResetOccupants()`: Forgets who is inside, without firing `Left`. Players still inside get `Entered` again on the next tick, which is useful when restarting a round.
- `void SetBounds(Vector3 a, Vector3 b)`: Moves both corners at once. They can be given in any order. On the next tick, players the zone no longer covers get `Left` and players it now covers get `Entered`.
- `string ToString()`
